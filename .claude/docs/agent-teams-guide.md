# Agent Teams 활용 가이드

## 개요

Agent Teams는 Claude Code의 실험적 기능으로, CEO가 복잡한 작업을 처리할 때 여러 전문가 에이전트를 조직화된 팀으로 운영할 수 있게 해줍니다. ClickSurvivor Hub에서는 **하이브리드 접근**으로 기본 Subagents(90%)와 선택적 Agent Teams(10%)를 자동으로 선택합니다.

## Subagents vs Agent Teams 선택 기준

### Subagents 사용 (기본, 90%)

**언제 사용하는가:**

- 순차적 작업 처리 필요
- 한 전문가가 완료 후 다음 전문가 순차 위임
- 대부분의 일상 업무

**예시:**

```
사용자 요청
  ↓
CEO: 버그 수정 필요 → developer에 위임
  ↓
developer: 수정 완료 → 테스트 필요 → qa-engineer에 위임
  ↓
qa-engineer: 테스트 완료 → 배포 필요 → infra-engineer에 위임
  ↓
infra-engineer: 배포 완료 → CEO에 보고
```

**장점:**

- 간단하고 예측 가능
- 컨텍스트 유지 용이
- 개별 의사결정이 명확

**적합 작업:**

- 기능 개발 (dev → qa → deploy)
- 문서 작성/검토
- 버그 수정 및 테스트
- 배포 전 체크리스트

---

### Agent Teams 사용 (선택적, 10%)

**언제 사용하는가:**

- 여러 전문가의 **병렬 작업** 필요
- **토론/합의**가 필요한 복잡한 의사결정
- 여러 관점의 의견 수렴 필요

**예시:**

```
사용자 요청: "새 로그인 기능 설계"
  ↓
CEO: Team 구성 → [designer, developer, security-ops]
  ↓
팀 활동:
  - designer: UI/UX 관점
  - developer: 구현 가능성
  - security-ops: 보안 고려사항
  ↓
팀원들이 서로 의견 교환 → 합의된 설계안 도출
  ↓
CEO에 최종 보고
```

**장점:**

- 다양한 관점 동시 검토
- 병렬 효율성
- 의견 충돌 해결 (팀 토론)

**적합 작업:**

- 아키텍처 결정 (기술/보안/성능 균형)
- 밸런스 조정 (게임/수익/플레이 경험)
- 보안 정책 수립 (개발/보안/법무)
- 대규모 리팩토링 계획

## CEO의 자동 판단 로직

CEO는 다음 기준으로 자동 선택합니다:

| 시나리오              | 선택        | 이유        |
| --------------------- | ----------- | ----------- |
| 작업이 순차적 (A→B→C) | Subagents   | 효율성      |
| 작업이 병렬 필요      | Agent Teams | 병렬성      |
| 의견 수렴 필요        | Agent Teams | 토론        |
| 단순 위임             | Subagents   | 단순성      |
| 복잡한 의사결정       | Agent Teams | 다각도 검토 |

**예:**

- "버그 수정" → Subagents (dev→qa→deploy)
- "밸런스 조정" → Agent Teams (designer+game-designer+security 토론)
- "문서 작성" → Subagents (docs-manager)
- "출시 전략" → Agent Teams (marketer+strategy+comms 협업)

## 사용자 관점

**사용자는 신경 쓸 필요 없습니다.**

평소대로 요청하면:

```
사용자: "프레스티지 밸런스를 더 어렵게 조정해줄 수 있을까?"
  ↓
CEO가 자동으로 판단:
- 이건 의견 수렴이 필요한 복잡한 의사결정
- Agent Teams 활용 (game-designer + designer + strategy-analyst)
  ↓
CEO: 팀 구성하고 작업 할당
  ↓
팀원들이 협력해서 해결
  ↓
CEO: 최종 보고
```

사용자가 할 일:

1. 평소처럼 요청
2. CEO를 통해 처리
3. 결과 받기

그게 전부입니다.

## 활성화 방법

이미 활성화되어 있습니다. `.claude/settings.json`에서:

```json
{
  "features": {
    "agentTeams": true
  }
}
```

변경 불필요 - CEO가 알아서 활용합니다.

## 아키텍처

### 구성 요소

**팀 리더 (CEO)**

- 팀 구성
- 작업 할당
- 결과 수렴

**팀원들 (전문가 에이전트)**

- 할당 받은 작업 처리
- 다른 팀원과 소통
- 의견 제시 및 합의

**작업 목록 (Task List)**

- 할당 받은 작업들
- 진행 상태 추적
- 우선순위 관리

**메일박스 (Mailbox)**

- 팀원 간 메시지 교환
- 토론 기록
- 합의 문서

### 데이터 흐름

```
CEO 요청
  ↓
팀 생성 (팀 리더/ID 자동 할당)
  ↓
작업 분배 (각 팀원에게 Task)
  ↓
병렬 처리 (팀원들이 각자 작업)
  ↓
토론/협력 (메일박스에서 의견 교환)
  ↓
합의 도출 (공동 결론)
  ↓
결과 반환 (CEO에게 최종 보고)
```

## 제한 사항 (실험적 기능)

**현재 한계:**

- 팀 규모: 최대 5명 (너무 크면 효율성 저하)
- 작업 복잡도: 중간 정도 (극도로 복잡한 의사결정은 불가)
- 실행 시간: 병렬이지만 여전히 순차보다 느림 (토론 오버헤드)
- 기능 신규성: 아직 실험 단계이므로 예상 밖 동작 가능

**권장 사항:**

- 긴급 작업에는 Subagents 사용 (더 빠름)
- 중요한 의사결정에 Agent Teams 사용 (품질 우선)
- 5명 이상 필요하면 재구성 (두 개 팀으로 나누기)

## 모범 사례

### 효과적인 Agent Teams 사용

**좋은 예:**

```
작업: "모바일 UI 개선과 성능 최적화"

CEO: 두 분야의 의견 수렴 필요
  → designer (UI/UX)
  → developer (성능)
  → security-ops (보안 고려)

결과: 균형잡힌 솔루션
```

**나쁜 예:**

```
작업: "로그인 버그 수정"

❌ CEO: 모든 전문가 팀 구성
  → 이건 순차 작업 (버그 수정 → 테스트 → 배포)
  → Agent Teams 오버킬

✓ CEO: Subagents 사용 (dev → qa → deploy)
  → 빠르고 효율적
```

### 팀 구성 전략

**기능 개발 (순차) → Subagents**

- 1명: developer 또는 designer

**의사결정 (토론) → Agent Teams**

- 3-4명: 주요 이해관계자들
- 예: 밸런스 변경 (game-designer + designer + strategy-analyst)

**운영 이슈 (협업) → Agent Teams**

- 2-3명: 관련 전문가
- 예: 배포 이슈 (infra-engineer + developer + security-ops)

**FAQ:**

**Q: 사용자가 명시적으로 "팀 구성해서 처리"라고 요청하면?**
A: CEO가 명시적 요청을 우선합니다. 하지만 불필요하면 더 효율적인 방법을 제안할 수 있습니다.

**Q: 팀 토론이 합의에 못 도달하면?**
A: CEO가 최종 중재자 역할을 합니다. 팀 의견을 종합하고 최종 결정을 내립니다.

**Q: Agent Teams는 언제 정식 기능화되나?**
A: 현재 실험적 기능입니다. 안정성이 확인되면 정식 기능으로 전환될 예정입니다.

**Q: Subagents 사용 중에 의견 수렴이 필요해지면?**
A: CEO가 언제든 Subagents → Agent Teams로 전환할 수 있습니다. (유동적 선택)
