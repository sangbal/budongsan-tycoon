## 5.1. 온보딩 철학 & 심리학적 기반

### 5.1.1. First-Time User Experience (FTUE) 설계 원칙

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    FTUE DESIGN PRINCIPLES                                   │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  "플레이어가 '배운다'고 느끼면 이미 실패한 것이다."                          │
│  - Nintendo 온보딩 철학                                                     │
│                                                                             │
│  [핵심 목표]                                                                │
│  ├─ 10분 내 핵심 루프 체험 (자원→가공→김치→보상)                           │
│  ├─ 15분 내 첫 자동화 라인 완성의 성취감                                   │
│  ├─ 20분 내 자유 플레이로 전환 (탐험 욕구 자극)                            │
│  └─ 이탈률 < 15% (업계 평균 30% 대비)                                      │
│                                                                             │
│  [KIMCHI INVASION 온보딩 3원칙]                                             │
│                                                                             │
│  1. SHOW, DON'T TELL                                                        │
│     └─ 텍스트 < 시각적 유도 < 직접 행동                                    │
│     └─ 튜토리얼 텍스트 총량 < 500자                                        │
│                                                                             │
│  2. FAIL-SAFE SANDBOX                                                       │
│     └─ 튜토리얼 중 실패 불가능 (자원 무한 공급)                            │
│     └─ 잘못된 배치 자동 수정 힌트                                          │
│                                                                             │
│  3. NARRATIVE DISGUISE                                                      │
│     └─ 학습이 아닌 '미션 수행' 프레임                                      │
│     └─ 대원들의 요청 = 게임 메카닉 학습                                    │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 5.1.2. 인지 부하 이론 (Cognitive Load Theory)

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    COGNITIVE LOAD MANAGEMENT                                │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  John Sweller의 인지 부하 이론 적용:                                        │
│                                                                             │
│  [내재적 부하 (Intrinsic Load)]                                             │
│  └─ 게임 메카닉 자체의 복잡성                                              │
│  └─ 최소화 전략: 단순→복잡 순차 공개                                       │
│     ├─ 1단계: 클릭만으로 자원 수집                                         │
│     ├─ 2단계: 건물 배치 (드래그 앤 드롭)                                   │
│     ├─ 3단계: 레시피 개념 (입력→출력)                                      │
│     ├─ 4단계: 물류 연결 (컨베이어)                                         │
│     └─ 5단계: 복합 생산 라인                                               │
│                                                                             │
│  [외재적 부하 (Extraneous Load)]                                            │
│  └─ 불필요한 UI/정보로 인한 혼란                                           │
│  └─ 최소화 전략:                                                           │
│     ├─ 튜토리얼 중 HUD 단계적 공개                                         │
│     ├─ 비활성 버튼 숨김 (회색 처리 아님)                                   │
│     ├─ 한 화면에 하나의 행동만 유도                                        │
│     └─ 애니메이션 속도 조절 (급하지 않게)                                  │
│                                                                             │
│  [유효 부하 (Germane Load)]                                                 │
│  └─ 실제 학습에 사용되는 인지 자원                                         │
│  └─ 극대화 전략:                                                           │
│     ├─ 즉각적 피드백 (행동→결과 0.5초 이내)                               │
│     ├─ 시각적 인과관계 강조 (화살표, 하이라이트)                           │
│     ├─ 작은 성공 경험 누적 (micro-rewards)                                 │
│     └─ 스키마 형성 유도 ("이건 ○○와 비슷하네")                            │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```
