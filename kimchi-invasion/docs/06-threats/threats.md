## 6.1. 위협 시스템 철학 (Threat Design Philosophy)

### 6.1.1. 왜 위협인가?

> **"위협 없는 공장은 그저 스크린세이버일 뿐이다."**

위협 시스템은 단순한 난이도 조절이 아닌, 플레이어의 **문제 해결 능력**과 **계획 수립 역량**을 시험하는 핵심 게임플레이 요소다.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    🎯 위협 시스템의 목적                                     │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  1️⃣  긴장감 곡선 (Tension Curve)                                            │
│      • 평화로운 건설 → 위기 → 해결의 반복 사이클                            │
│      • 지속적인 성장만으로는 지루함 유발                                     │
│      • 위협은 게임에 리듬과 호흡을 부여                                      │
│                                                                             │
│  2️⃣  플레이어 에이전시 (Player Agency)                                      │
│      • 모든 위협에는 대응 방법이 존재                                        │
│      • 준비된 플레이어는 위협을 기회로 전환                                  │
│      • 예측 가능하지만 무시할 수 없는 설계                                   │
│                                                                             │
│  3️⃣  의미 있는 선택 (Meaningful Choices)                                    │
│      • 방어 vs 생산 투자 트레이드오프                                        │
│      • 단기 효율 vs 장기 안정성 결정                                         │
│      • 리스크 관리 vs 공격적 확장 전략                                       │
│                                                                             │
│  4️⃣  테마 강화 (Thematic Reinforcement)                                     │
│      • 화성은 인간에게 적대적인 환경                                         │
│      • 생존 자체가 업적이라는 서사 강화                                      │
│      • "개척자" 판타지의 핵심 요소                                           │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 6.1.2. 긴장감 곡선 모델 (Tension Curve Model)

```
긴장도
  ↑
100│                              ████
   │                           ███    ███
 75│            ████        ███          ███           ████
   │         ███    ███  ███               ███      ███    ███
 50│      ███          ██                     ███ ███         ███
   │   ███                                       █               ███
 25│███
   │
  0└──────────────────────────────────────────────────────────────────→ 시간
     건설     위협    해결    확장     위협    해결    건설     위협

  📊 이상적인 긴장감 분포:
  • 건설/확장 (30-40%): 평화로운 성장 시간
  • 위협 감지 (20%): 경고, 준비 단계
  • 위협 대응 (25-30%): 적극적 문제 해결
  • 해결/보상 (10-15%): 성취감, 휴식
```

      '방풍벽으로 모래폭풍 피해 감소',

    // 복구 가능성

      '건물 파괴 → 잔해에서 50% 자원 회수',
      '대원 사망 → 새 대원 모집 가능',
      '전체 정전 → 수동 재시작 가능',
    ],
    rationale: '완전한 손실은 이탈 유발',
  },
}
```

## 6.2. 환경 위협 (Environmental Hazards)

### 6.2.1. 모래폭풍 (Dust Storm)

> **"화성의 숨결은 때로 비명처럼 거세다."**

화성 대기의 95%는 이산화탄소지만, 미세한 철산화물 먼지가 수백 km/h의 속도로 휘몰아치면 태양광 패널을 뒤덮고 기계를 갈아먹는다.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    🌪️ 모래폭풍 시스템 상세                                   │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  ◆ 발생 메커니즘                                                            │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │ 계절    │ 발생 확률 │ 강도 배수 │ 비고                             │   │
│  ├─────────┼───────────┼───────────┼──────────────────────────────────┤   │
│  │ 봄      │ 15%/일    │ 1.0x      │ 평균적 빈도                      │   │
│  │ 여름    │ 30%/일    │ 1.5x      │ 폭풍 시즌                        │   │
│  │ 가을    │ 20%/일    │ 1.2x      │ 감소 추세                        │   │
│  │ 겨울    │ 5%/일     │ 0.8x      │ 희박한 대기                      │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  ◆ 강도 등급                                                                │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │ 등급   │ 시야    │ 태양광    │ 야외 건물 │ 지속 시간 │ 확률      │   │
│  ├────────┼─────────┼───────────┼───────────┼───────────┼───────────┤   │
│  │ 경미   │ 80%     │ -20%      │ 피해 없음 │ 1-2분     │ 60%       │   │
│  │ 보통   │ 50%     │ -50%      │ 1% HP/분  │ 2-5분     │ 30%       │   │
│  │ 강함   │ 20%     │ -80%      │ 3% HP/분  │ 5-10분    │ 8%        │   │
│  │ 극심   │ 5%      │ -95%      │ 5% HP/분  │ 10-20분   │ 2%        │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  ◆ 경고 시스템                                                              │
│  • T-60초: 레이더 탐지 "폭풍 접근 중 (방향: 북동)"                          │
│  • T-30초: 황색 경보 "폭풍 도달 예상: 30초"                                 │
│  • T-10초: 적색 경보 "즉시 대비하세요!"                                     │
│  • T-0초:  폭풍 시작 "폭풍 진입 - 예상 지속 시간: X분"                      │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘

### 6.2.4. 태양 플레어 (Solar Flare)

> **"태양이 재채기하면 화성의 모든 전자장비가 멈춘다."**

```javascript
// 태양 플레어 시스템
const SOLAR_FLARE_CONFIG = {
  frequency: {
    minor: { period_days: 30, variance: 10 }, // 월 1회
    major: { period_days: 180, variance: 30 }, // 반기 1회
    extreme: { period_days: 720, variance: 60 }, // 2년 1회
  },

  effects: {
    minor: {
      duration: 60, // 1분
      solar_boost: 1.2, // 태양광 +20%
      electronic_malfunction: 0.05, // 5% 확률로 오작동
      warning_time: 300, // 5분 전 경고
    },
    major: {
      duration: 300, // 5분
      solar_boost: 1.5, // 태양광 +50% (역설적)
      electronic_shutdown: true,
      unshielded_damage: 0.1, // 10% 피해
      warning_time: 600, // 10분 전 경고
    },
    extreme: {
      duration: 900, // 15분
      solar_boost: 2.0, // 태양광 +100%
      electronic_shutdown: true,
      emp_damage: 0.25, // 25% 피해
      crew_radiation: true, // 대원 방사선 노출
      warning_time: 1800, // 30분 전 경고
    },
  },

  mitigation: {
    emp_shielding: {
      cost: { iron_plate: 100, chipset: 10 },
      protection: 0.9, // 90% 피해 감소
    },
    faraday_dome: {
      cost: { iron_plate: 500, chipset: 50, rare_mineral: 20 },
      protection: 1.0, // 완전 보호
      coverage_radius: 15, // 타일
    },
    analog_backup: {
      research_cost: { lacto_data: 100 },
      effect: '기본 기능 수동 운영 가능',
    },
  },
}
```

## 6.8. 위협 스케줄러 (Threat Scheduler)

### 6.8.1. 위협 발생 알고리즘

```javascript
// 위협 스케줄러 엔진
const THREAT_SCHEDULER = {
  // 기본 스케줄링
  base_schedule: {
    check_interval: 60, // 60초마다 체크
    cooldown_after_event: 120, // 이벤트 후 2분 쿨다운
    max_concurrent: 2, // 동시 최대 2개 위협
  },

  // 위협 풀
  threat_pool: {
    dust_storm: {
      base_chance: 0.02, // 체크당 2%
      season_modifier: season => (season === 'summer' ? 2.0 : 1.0),
      cooldown: 600, // 10분
      stacks: false,
    },
    meteor: {
      base_chance: 0.01,
      size_weights: { micro: 0.7, small: 0.2, medium: 0.08, large: 0.02 },
      cooldown: 300,
      stacks: true, // 동시 다발 가능
    },
    equipment_failure: {
      base_chance: 0.005,
      building_count_modifier: count => 1 + count * 0.001,
      cooldown: 900,
      stacks: false,
    },
    solar_flare: {
      base_chance: 0.001,
      severity_weights: { minor: 0.7, major: 0.25, extreme: 0.05 },
      cooldown: 3600, // 1시간
      stacks: false,
    },
  },

  // 페이싱 룰
  pacing: {
    // 연속 위협 방지
    max_threats_per_hour: 5,
    // 진행도 기반 스케일링
    progression_multiplier: milestone => {
      const multipliers = { M1: 0.5, M2: 0.8, M3: 1.0, M4: 1.2, M5: 1.5 }
      return multipliers[milestone] || 1.0
    },
    // 플레이어 휴식 보장
    guaranteed_peace: {
      after_major_threat: 300, // 대형 위협 후 5분 평화
      after_milestone: 600, // 마일스톤 달성 후 10분 평화
      tutorial_mode: Infinity, // 튜토리얼 중 위협 없음
    },
  },
}

// 위협 발생 함수
function rollForThreats(gameState) {
  const scheduler = THREAT_SCHEDULER
  const activeThreatCount = gameState.activeThreats.length

  // 최대 동시 위협 체크
  if (activeThreatCount >= scheduler.base_schedule.max_concurrent) {
    return null
  }

  // 평화 시간 체크
  if (gameState.peacetimeRemaining > 0) {
    return null
  }

  // 각 위협 유형에 대해 롤
  for (const [threatType, config] of Object.entries(scheduler.threat_pool)) {
    // 쿨다운 체크
    if (gameState.threatCooldowns[threatType] > 0) continue

    // 확률 계산
    let chance = config.base_chance
    chance *= scheduler.pacing.progression_multiplier(gameState.milestone)

    if (config.season_modifier) {
      chance *= config.season_modifier(gameState.season)
    }
    if (config.building_count_modifier) {
      chance *= config.building_count_modifier(gameState.buildingCount)
    }

    // 롤
    if (Math.random() < chance) {
      return createThreat(threatType, config, gameState)
    }
  }

  return null
}
```
